# Ubiquitous Language

> **Purpose**
>
> This document defines the common business vocabulary used throughout
> DecisionOS.
>
> Every developer, researcher, designer, and AI engineer should use these
> definitions consistently.
>
> If a term is not defined here, it should not become part of the core domain
> without discussion.

---

# User

A User is an individual or organization that owns one or more decisions and
uses DecisionOS to improve decision quality.

A user is **not** simply someone with an account.

The user represents the owner of decisions, preferences, history, goals and
personal context.

Examples

- Student
- Software Engineer
- Founder
- Researcher
- Family
- Small Business

---

# Decision

A Decision is the primary business object in DecisionOS.

A decision represents a problem that requires choosing one or more options
under uncertainty.

Every decision has:

- objective
- context
- constraints
- options
- evaluation
- recommendation
- outcome

Examples

- Should I pursue a Master's degree?
- Should I accept this job offer?
- Should I move to Germany?
- Should I postpone today's workout?

---

# Decision Context

Decision Context is all information required to understand a decision.

Context can come from multiple sources.

Examples

- User profile
- Calendar
- Goals
- Budget
- Health
- Location
- Documents
- Previous decisions
- Current market conditions
- External APIs

Context is dynamic and may change over time.

---

# Decision Profile

A Decision Profile is the structured long-term representation of a user.

Unlike conversation history, the Decision Profile stores durable information.

Examples

- Education
- Skills
- Experience
- Languages
- Financial capacity
- Family responsibilities
- Career goals
- Risk tolerance
- Preferences
- Values

The Decision Profile changes slowly over time.

---

# Goal

A Goal is a desired future outcome the user wants to achieve.

Goals influence how options are evaluated.

Examples

- Become an AI Engineer
- Study in Germany
- Build a profitable startup
- Improve health
- Achieve financial independence

A user may have multiple goals.

Goals may also conflict.

---

# Constraint

A Constraint is any limitation that restricts available options.

Examples

- Budget
- Time
- Visa eligibility
- Family commitments
- Health condition
- Legal requirements
- Deadlines

Constraints determine whether an option is feasible.

---

# Option

An Option is a possible course of action that can satisfy a decision.

Examples

Decision

Should I pursue higher education?

Options

- Germany
- Finland
- Stay in Nepal
- Work first
- Start a company

A decision must have at least one option.

---

# Evidence

Evidence is any information used to support or reject an option.

Evidence may originate from:

- User data
- Uploaded documents
- Calendar
- Web search
- Market reports
- Academic papers
- Government websites
- Internal calculations

Evidence should always be traceable.

DecisionOS should avoid unsupported recommendations.

---

# Evaluation

Evaluation is the process of analyzing an option against one or more criteria.

Typical evaluation criteria include

- Cost
- Career Growth
- Time
- Risk
- Health
- Family
- Opportunity Cost
- Return on Investment

Each option may have multiple evaluations.

---

# Risk

Risk represents the possibility that an option leads to an undesirable outcome.

Every identified risk should include

- Description
- Likelihood
- Impact
- Severity
- Mitigation Strategy

Risk is evaluated independently from benefits.

---

# Recommendation

A Recommendation is the final output produced by DecisionOS.

A recommendation contains

- Recommended option
- Confidence level
- Supporting evidence
- Trade-offs
- Risks
- Assumptions
- Explanation

DecisionOS should never produce recommendations without explanation.

---

# Confidence

Confidence represents how certain DecisionOS is about a recommendation.

Confidence is influenced by

- Context completeness
- Evidence quality
- Data freshness
- Model agreement
- External uncertainty

Confidence is not a probability of correctness.

It is an estimate of recommendation reliability.

---

# Outcome

Outcome represents the real-world result after a decision has been made.

Examples

Recommendation

↓

User accepts job offer

↓

Six months later

↓

Promotion received

Outcome enables continuous learning.

---

# Decision History

Decision History is the collection of all previous decisions and their outcomes.

It allows DecisionOS to

- identify patterns
- avoid repeated mistakes
- personalize recommendations
- improve future reasoning

---

# Integration

An Integration connects DecisionOS with an external system.

Examples

- Google Calendar
- Gmail
- GitHub
- LinkedIn
- Notion
- Slack
- Banking APIs

Integrations provide contextual information.

---

# Memory

Memory is information retained by DecisionOS beyond a single conversation.

Memory consists of multiple categories.

- Profile Memory
- Decision Memory
- Knowledge Memory
- Experience Memory

Different memory types have different storage strategies.

---

# Knowledge

Knowledge represents reusable information that supports reasoning.

Examples

- University admission requirements
- Visa rules
- Financial planning principles
- Career frameworks
- Medical guidelines

Knowledge may come from internal databases or external sources.

---

# Assumption

An Assumption is information inferred when complete data is unavailable.

Every assumption should be explicitly identified.

DecisionOS should encourage users to validate important assumptions before
making high-impact decisions.

---

# Workflow

A Workflow is the sequence of activities required to analyze and complete a
decision.

Example

Decision Request

↓

Context Collection

↓

Evidence Gathering

↓

Option Generation

↓

Evaluation

↓

Risk Assessment

↓

Recommendation

↓

Outcome Tracking

Workflows coordinate the decision process but are not themselves business
entities.
