# Domain Model

## Purpose

Defines the core business concepts of DecisionOS and their relationships.
This document is technology-independent and serves as the foundation for database design, APIs, workflows, and AI architecture.

---

# Core Domain

The core domain of DecisionOS is **Decision Intelligence**.

The platform helps users make better decisions by combining personal context, structured reasoning, external information, and AI.

---

# Core Concepts

| Concept | Description |
|----------|-------------|
| User | Person or organization using DecisionOS. |
| Decision | A problem requiring one or more possible solutions. |
| Context | Information relevant to a specific decision. |
| Profile | Long-term information about a user. |
| Goal | Desired outcome the user wants to achieve. |
| Constraint | Limitation that affects a decision. |
| Option | One possible solution to a decision. |
| Evidence | Information supporting or rejecting an option. |
| Evaluation | Analysis of an option against defined criteria. |
| Risk | Potential negative outcome of an option. |
| Recommendation | Final ranked result produced by DecisionOS. |
| Outcome | Actual result after the user acts. |

---

# Domain Relationships

```text
User
│
├── Profile
├── Goals
├── Decisions
└── Integrations

Decision
│
├── Context
├── Constraints
├── Options
├── Evaluations
├── Risks
├── Recommendation
└── Outcome
```

---

# Core Entities

## User

**Purpose**

Owns decisions and maintains long-term information.

**Contains**

- Profile
- Goals
- Integrations
- Decision History

---

## Decision

**Purpose**

Represents a problem to be analyzed.

**Contains**

- Context
- Constraints
- Options
- Recommendation
- Outcome

---

## Profile

**Purpose**

Stores long-term user information.

**Examples**

- Education
- Experience
- Skills
- Preferences
- Risk Tolerance

---

## Context

**Purpose**

Stores information relevant to the current decision.

**Examples**

- Calendar
- Deadlines
- Budget
- Location
- Current Tasks

---

## Goal

**Purpose**

Represents a desired future outcome.

Examples:

- Master's Abroad
- Financial Freedom
- Startup
- Better Health

---

## Constraint

**Purpose**

Represents a limitation.

Examples:

- Budget
- Time
- Visa
- Health

---

## Option

**Purpose**

Represents one possible solution.

Every decision has one or more options.

---

## Evaluation

**Purpose**

Scores an option against one or more criteria.

Typical Criteria

- Cost
- Time
- Career Growth
- Health
- ROI
- Family Impact

---

## Risk

**Purpose**

Represents uncertainty associated with an option.

Contains

- Likelihood
- Impact
- Mitigation

---

## Recommendation

**Purpose**

Represents the final output generated by DecisionOS.

Contains

- Best Option
- Confidence
- Evidence
- Risks
- Explanation

---

## Outcome

**Purpose**

Represents what happened after the user made a decision.

Used for continuous learning.

---

# Business Rules

- Every Decision belongs to one User.
- Every Decision must have at least one Option.
- Every Recommendation belongs to one Decision.
- Every Recommendation is supported by Evidence.
- A Decision may have multiple Constraints.
- A Decision may have multiple Evaluations.
- Outcome is optional until the decision is completed.
