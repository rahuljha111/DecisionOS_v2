# DecisionOS AI Coding Rules

## Architecture

- Follow Clean Architecture.
- Keep modules independent.
- Never bypass service layer.
- No business logic in routers.
- Repositories only access the database.

## Code Style

- Use Python type hints everywhere.
- Follow existing naming conventions.
- Reuse existing utilities before creating new ones.
- Avoid duplicate code.
- Keep functions small and focused.

## API

- Use Pydantic models.
- Preserve backward compatibility unless requested.
- Return consistent API responses.

## Database

- SQLAlchemy ORM only.
- No raw SQL unless justified.
- Alembic migrations for schema changes.

## Testing

- Update or add tests for new behavior.
- Don't break existing tests.

## General

- Explain major architectural decisions before making sweeping changes.
- Prefer incremental refactors over large rewrites.
